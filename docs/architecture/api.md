# API

> The OpenAPI document generated by FastAPI **is** the contract. This page defines conventions and
> the endpoint catalog that issues implement. When implementing, keep this catalog in sync, but the
> generated OpenAPI wins for exact shapes.

## 1. Conventions

| Topic | Convention |
|-------|------------|
| Base path | `/api/v1`. Vault-scoped resources live under `/api/v1/vaults/{vault_id}/…`. Module routes under `/api/v1/vaults/{vault_id}/m/{module_id}/…`. |
| Format | JSON (`application/json`), `snake_case` field names end to end (the TS client uses the generated types as-is). Uploads are `multipart/form-data`; downloads are files. |
| IDs | UUID strings. |
| Big integers | **Decimal strings** (moments, durations, counts, field integers). OpenAPI: `type: string`, `format: bigint`, with a `pattern`. |
| Time context | Optional query params on reads: `timeline=<id>` (default: the dimension's prime timeline) and `at=<moment>` (as-of). |
| Pagination | Cursor based: `?limit=50&cursor=…` returns `{items, next_cursor}`. `limit` ≤ 500. |
| Sorting/filtering | Query params documented per endpoint. Unknown params are rejected (`422`). |
| Concurrency | Mutable resources return `revision`. `PATCH` requires `revision` in the body, and a mismatch returns `409 revision_conflict` with the current resource. |
| Composite writes | Create/patch of an entity accepts inline `aliases`, `tags`, `links_add`, `links_remove` and kind extension data (`ext`), so common UI actions are **one transaction = one changeset**. |
| Errors | RFC 9457 `application/problem+json`: `{type, title, status, detail, code, errors?: [{path, code, message}], context?}`. `code` is a stable machine identifier (§3). |
| CSRF guard | Every non-GET request must send `X-Lore-Client: web` (or `cli`), otherwise `403 missing_client_header` (see `security.md`). |
| Read-only mode | Every non-GET request returns `403 read_only`. Reads are visibility-filtered (`visibility-and-sharing.md`). |
| Reader preview | Author mode accepts `?as_reader=true` on reads to apply reader filtering. |
| OpenAPI hygiene | Explicit `operation_id` (`<area>_<action>`, e.g. `entities_get`), tags per area/module, response models for every route, examples for time-related schemas. |
| Versioning | Breaking changes are coordinated in the same repo (frontend + backend in one PR), so `/api/v1` stays until a public consumer exists (e.g. an MCP module). Static-export snapshots carry their own format version. |

## 2. Endpoint catalog (MVP)

`{v}` = vault id. All paths are relative to `/api/v1`.

### System

| Method | Path | Purpose |
|--------|------|---------|
| GET | `/health` | liveness (+ DB check of loaded vaults) |
| GET | `/meta` | `{app_version, api_version, read_only, exposed_vaults, features}` |

### Vaults & settings

| Method | Path | Purpose |
|--------|------|---------|
| GET/POST | `/vaults` | list / create (`{name}`) |
| GET/PATCH/DELETE | `/vaults/{v}` | read / rename / move to data trash |
| POST | `/vaults/{v}/migrate` | run pending migrations (when auto-migrate is off) |
| GET | `/vaults/{v}/registry` | kinds, field types, field defs, link types, modules, consistency rules (drives the generic UI) |
| PATCH | `/vaults/{v}/modules/{module_id}` | enable/disable (`{enabled, cascade?}`) |
| GET/PATCH | `/vaults/{v}/settings` | display prefs, defaults, backup schedule |
| GET/POST | `/vaults/{v}/backups` | list / create backup |
| GET | `/vaults/{v}/backups/{id}/download` | download zip |
| POST | `/vaults/restore` | restore a backup zip into a new vault |

### Entities (generic, all kinds)

| Method | Path | Purpose |
|--------|------|---------|
| GET | `/vaults/{v}/entities` | list/filter: `kind, dimension, parent, tag, q, include_multiversal, include_trashed, sort, cursor, limit, timeline, at` (at → existence filter) |
| POST | `/vaults/{v}/entities` | create any kind (`{kind, name, …, ext}`) |
| GET | `/vaults/{v}/entities/{id}` | full entity: core fields, `ext`, aliases, tags, `state` (if `at`) |
| PATCH | `/vaults/{v}/entities/{id}` | update (revision required) |
| DELETE | `/vaults/{v}/entities/{id}` | move to trash (`?purge=true` for permanent, author only) |
| POST | `/vaults/{v}/entities/{id}/restore` | restore from trash |
| GET | `/vaults/{v}/entities/{id}/children` | children by `parent_id` (sorted) |
| GET | `/vaults/{v}/tree` | lazy navigation tree: `dimension, parent, kinds` |
| GET | `/vaults/{v}/entities/{id}/links` | outgoing/incoming links: `direction, type, timeline, at` |
| GET | `/vaults/{v}/entities/{id}/backlinks` | incoming links and mentions |
| GET | `/vaults/{v}/entities/{id}/unlinked-mentions` | name/alias occurrences without links |
| GET | `/vaults/{v}/entities/{id}/history` | per-entity changes |
| GET | `/vaults/{v}/entities/{id}/state` | as-of state (`timeline, at`) per `time-model.md` §10.5 |
| GET/POST | `/vaults/{v}/entities/{id}/facts` | list/create temporal facts (`field`, `timeline`) |
| PATCH/DELETE | `/vaults/{v}/facts/{id}` | update/trash a fact |
| GET | `/vaults/{v}/trash` | trashed entities |

### Links & link types

| Method | Path | Purpose |
|--------|------|---------|
| POST | `/vaults/{v}/links` | create |
| PATCH/DELETE | `/vaults/{v}/links/{id}` | update / trash |
| GET/POST | `/vaults/{v}/link-types` | list (built-in + custom) / create custom |
| PATCH | `/vaults/{v}/link-types/{key}` | edit/archive a custom type |

### Time

| Method | Path | Purpose |
|--------|------|---------|
| POST | `/vaults/{v}/dimensions` | wizard: dimension + prime timeline + first calendar (from preset or definition) in one transaction |
| GET | `/vaults/{v}/dimensions/{id}/timelines` | timeline tree |
| GET | `/vaults/{v}/calendars/presets` | preset catalog |
| POST | `/vaults/{v}/calendars/preview` | compile an unsaved definition in a dimension context: errors, sample conversions |
| POST | `/vaults/{v}/calendars/{id}/proposals` | calendar edit impact preview (`time-model.md` §7.4) |
| POST | `/vaults/{v}/calendars/{id}/proposals/{pid}/apply` | apply with per-record strategies |
| POST | `/vaults/{v}/time/resolve` | batch-resolve time points (validation for pickers; returns moment, status, display) |
| POST | `/vaults/{v}/time/convert` | batch moment → fields/format in given calendars (for non-TS clients and tests) |
| GET | `/vaults/{v}/timelines/{id}/window` | timeline view data: `from, to, px, min_importance, kinds, tags, participants, include_series` → `{items, series_bands, buckets}` |
| GET | `/vaults/{v}/timelines/{id}/event-tree` | event outline (`parent`, lazy) |
| GET | `/vaults/{v}/events/{id}/occurrences` | computed + materialized occurrences in `[from, to)` |
| POST | `/vaults/{v}/events/{id}/occurrences/{key}` | materialize (get-or-create) |
| POST | `/vaults/{v}/events/{id}/recurrence/proposals` (+ `/{pid}/apply`) | rule-change reconciliation (`recurrence.md` §8) |

### Advanced time (modules `branches`, `correspondences`, `worldlines`)

| Method | Path | Purpose |
|--------|------|---------|
| POST | `/vaults/{v}/m/branches/timelines` | create a branch (`{dimension, parent_timeline, branch_point, name}`) |
| POST | `/vaults/{v}/m/branches/overrides` | create an override row for a spanning record (`{record_type, root_id, timeline, changes}`) |
| GET | `/vaults/{v}/m/branches/timelines/{id}/diff` | records differing from the parent (comparison view) |
| GET/POST | `/vaults/{v}/m/correspondences` | list / create |
| GET/PATCH/DELETE | `/vaults/{v}/m/correspondences/{id}` | read / update (points included) / trash |
| GET | `/vaults/{v}/m/correspondences/map` | `from_dimension, to_dimension, t` → mapped moment (+ path used) |
| GET/PUT | `/vaults/{v}/m/worldlines/entities/{id}/segments` | read / replace the ordered segment list |
| GET | `/vaults/{v}/m/worldlines/entities/{id}/personal-timeline` | experienced items in subjective order |

### Search, graph, consistency, history

| Method | Path | Purpose |
|--------|------|---------|
| GET | `/vaults/{v}/search` | `q, kinds, dimension, limit, cursor` → hits with highlighted snippets (entities + module docs) |
| GET | `/vaults/{v}/search/quick` | quick switcher (names/aliases, prefix + trigram) |
| GET | `/vaults/{v}/m/graph/graph` | `dimension, center, depth, kinds, link_types, include_mentions, tags, timeline, at` → `{nodes, edges}` |
| GET | `/vaults/{v}/consistency/findings` | `status, severity, rule, entity, cursor` |
| POST | `/vaults/{v}/consistency/scan` | full re-scan |
| GET/PATCH | `/vaults/{v}/consistency/rules` (`/{rule_id}`) | list rules / set severity |
| POST/DELETE | `/vaults/{v}/consistency/suppressions` (`/{fingerprint}`) | suppress / unsuppress a finding |
| GET | `/vaults/{v}/changes` | recent changes feed |
| GET | `/vaults/{v}/changes/{id}` | changeset detail |
| POST | `/vaults/{v}/changes/{id}/revert` | undo a changeset |

## 3. Error codes (initial set)

`not_found`, `validation_error`, `revision_conflict`, `module_disabled`, `read_only`,
`missing_client_header`, `vault_not_found`, `vault_locked`, `vault_needs_migration`,
`vault_newer_than_app`, `time_cycle`, `time_constraint` (hard structural violation; `errors`
lists records), `invalid_date`, `reform_gap`, `reform_ambiguous`, `calendar_invalid` (`errors`
from the engine), `rule_invalid`, `proposal_stale`, `proposal_unresolved`,
`dimension_has_no_calendar`, `parent_not_allowed`, `link_type_not_allowed`,
`override_not_allowed`, `upload_rejected`, `revert_conflict`, `consistency_error` (an
error-severity rule blocks the write; `errors` lists findings).

## 4. Static-export compatibility

Reader-mode screens must only use read endpoints that the post-MVP `StaticDataSource` can serve
from a snapshot. The authoritative list lives in `visibility-and-sharing.md` §6. New reader-facing
endpoints must be added to that list in the same PR.
